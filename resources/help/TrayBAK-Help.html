TrayBAK Help

Scheduled folder backups from the Windows system tray.

Overview

TrayBAK backs up folders on a schedule and keeps running quietly in the notification area of the taskbar. Each folder you want to protect is a job. Every job has its own source folder, backup folder, schedule, retention rules and alert settings.

  • Backups are standard .zip files you can open with Windows Explorer or any archive tool.
  • Up to 10 jobs.
  • Back up a whole folder, or only the files and folders you tick.
  • Schedules: manual, every X minutes, hourly, daily at a set time, or weekly on chosen days.
  • A failed scheduled backup is retried automatically.
  • Old backups are removed automatically by age and by count.
  • A full action log records every backup, failure, and change.
  • Alerts are local: a popup near the tray and a sound. Nothing is sent over the network.

Requirements

  • Windows 10 or 11, 64 bit.
  • The Microsoft .NET 10 Desktop Runtime must be installed on the PC. TrayBAK does not bundle it.
  • TrayBAK is portable: copy its folder anywhere you can write to and run TrayBAK.exe. See Where things are stored.

Quick start

  1. Open TrayBAK and choose Add job.
  2. Give the job a name, pick the folder to back up and the folder where backups should be stored.
  3. Choose a schedule. A new job starts as Daily at a set time at 12:00. Change the type or time as needed, for example to 03:50.
  4. Set how long to keep backups, for example 30 days.
  5. Choose Save. Select the job and choose Run now to test it.
  6. Close the window. TrayBAK keeps running in the tray and runs the job on schedule.
Example: a daily server folder backup. Source folder: the folder to protect. Schedule: Daily at 03:50. Keep: delete backups older than 30 days. The result is one zip per day and the most recent 30 days available at any time.

Missed backups

If TrayBAK was closed or the PC was off at the scheduled time, the job runs as soon as TrayBAK is running again, provided Run a missed backup is ticked on the job. If it is not ticked, the missed run is skipped and the job waits for its next scheduled time.

One at a time

Only one backup runs at a time. If several jobs are due together, the others wait in a queue and show Queued.

Retrying a failed backup

If a scheduled backup fails, for example because the backup drive was offline, TrayBAK tries again after a short wait. The number of tries and the wait are set in Tools > Options (default: up to 3 retries, 10 minutes apart). The Next run column shows Retry and the time while a retry is waiting.

  • Only scheduled backups are retried. A backup you start by hand is not.
  • If the next scheduled time arrives first, that run goes ahead and replaces the pending retry.
  • The failure alert is shown only when the last try fails. Every try is recorded in the log.
  • Retries are forgotten when TrayBAK exits. The job simply runs at its next scheduled time.

Pausing

Use Tools > Pause scheduling or the tray menu to stop all scheduled runs. Manual runs still work. When you resume, jobs that were due run if they are set to run missed backups.

Choosing files and folders

By default a job backs up everything in its source folder. To back up only part of it, choose Choose files and folders... in the job editor. A tree of the source folder opens with a check box on every folder and file.

  • Untick anything you do not want. Unticked items are skipped.
  • A ticked folder includes everything inside it, including files and folders added later, so new things are never silently left out.
  • A folder showing a filled square is partly ticked: something inside it is unticked.
  • Clicking a partly ticked folder ticks everything inside it.
  • Select all and Clear all change everything at once. At least one item must stay ticked.
  • Back up everything in the job editor removes all unticked items.

The tree reads folders only when you expand them, so large folders open quickly. The choices are saved as paths relative to the source folder. If you change the source folder of a job, the choices are cleared because they no longer apply.

Excluded patterns (see below) work together with the tree: an item is skipped if it is unticked or matches a pattern.

Excluding files

Enter one pattern per line in the Exclude box. Patterns are not case sensitive and support * (any characters) and ? (one character).

PatternExcludes
objAny file or folder named obj, at any depth.
*.tmpEvery file ending in .tmp.
logsEvery folder or file named logs.
data/cacheOnly cache inside data, counted from the source folder. A pattern containing a slash is matched against the path from the source folder.

Excluded folders are skipped completely, including everything inside them. Shortcuts and linked folders (reparse points) are not followed.

If the backup folder is inside the source folder it is skipped automatically.

Backup files and naming

Each backup is a single zip file. It is stored in a sub folder named after the job, inside the backup folder you chose. For a backup folder of D:\Backups and a job called Oxide:

D:\Backups\Oxide.log
D:\Backups\Oxide\Oxide_10-17-2026_03-50-00.zip
D:\Backups\Oxide\Oxide_10-18-2026_03-50-01.zip

The zip file names look like this:

JobName_MM-dd-yyyy_HH-mm-ss.zip

Oxide_10-17-2026_03-50-00.zip
Oxide_10-18-2026_03-50-01.zip

The name carries the date and the 24 hour time the backup was made, down to the second. Characters that Windows does not allow in file names are replaced with an underscore. If two backups of the same job would fall in the same second, the later one is stamped one second ahead, so a name is never reused.

Each job also keeps one status log, named after the job, for example Oxide.log. It stays in the backup folder itself, next to the job's sub folder, not inside it. Every run adds one line: the date and time, OK, FAILED or CANCELLED, the zip name, the file count, size and duration. Failures show the reason, and files that could not be read are listed under the line. The log is trimmed automatically when it passes 1 MB and is never removed by the retention rules.

Inside the zip, everything sits under one top level folder named after the source folder, so extracting never scatters files.

A backup is written to a temporary file ending in .tmp and renamed only when it is complete. A failed or cancelled run never leaves a partial zip behind.

Keeping backups

Two limits are available. Use either, both, or neither. A value of 0 means no limit.

  • Delete backups older than X days. With 30, today and the previous 29 days are kept.
  • Keep only the newest X backups. Useful for jobs that run several times a day.

When both are set, a backup is removed if it breaks either limit.

  • Cleanup runs only after a new backup finishes successfully, so a failing job never deletes its older backups.
  • The backup just created is never deleted.
  • Only files that match the job's own naming pattern are ever deleted. Other files in the job's sub folder are left alone.
Job names are unique. Retention matches files by job name, so two jobs can never share a name.

Restoring

Select a job and choose Open backups, then open or extract the zip you want with Windows Explorer or an archive tool. TrayBAK does not restore files itself, so nothing is overwritten by accident.

Files that were in use when the backup ran are read with shared access. A file that is being written at that moment can be captured part way through. For applications that keep complex data files, schedule backups for a quiet time of day.

A file that cannot be read at all, such as one locked exclusively, is skipped and counted. The job details and the log show how many were skipped.

Closing the main window hides it to the tray. Use File > Exit or the tray menu to quit completely. If a backup is running you are asked first.

Alerts

Each job can alert when a backup completes, when it fails, or both. By default only failures alert.

  • Popup: a small message above the tray. Click it to dismiss. Errors stay a little longer.
  • Sound: the standard Windows sounds for information and errors.

Popups and sounds can be switched off in Tools > Options. Cancelled backups do not alert.

The log

Everything TrayBAK does is recorded: starts, completions, failures, skipped files, job changes, pausing, and program start and stop. The lower half of the main window shows the newest entries.

Open View > Log viewer to filter by level or job and to search the text. Entries are kept for the number of days set in Options.

The program log is also a plain text file, logs\traybak.log, with one line per event: date and time, level, job and message. Use View > Open logs folder to find it. Each job also keeps its own status log in its backup folder, described under Backup files and naming.

Where things are stored

ItemLocation
Settings and jobsconfig\settings.json in the folder that holds TrayBAK.exe
Program loglogs\traybak.log in the same folder. Plain text, one line per event: date and time, level, job, message.
Error detailslogs\errors.log is written only if TrayBAK hits an unexpected error. It holds the technical details.
Backups and their logsThe backup folder you choose for each job. Zips are in a sub folder named after the job. The job's log file is in the backup folder itself.

Tools > Options > Open logs folder (also under View) opens the logs folder.

TrayBAK is portable. Nothing is stored in AppData or the registry, except the optional Start when I sign in setting, which records the program's current location. To move TrayBAK to another PC or drive, copy the whole folder, including config (and logs if you want the history). The folder must be one you can write to, so do not put it in Program Files.

Troubleshooting

The job says Failed

Select the job and read the Details column, or open the log. Common causes: the source folder was moved or renamed, the backup drive or network share is offline, or the backup drive is full.

A job did not run at its time

  • Is the job enabled and is scheduling paused?
  • Was TrayBAK running at that time? It only runs while open in the tray.
  • Check the Next run column for the time TrayBAK expects.

Some files were skipped

Those files were locked by another program. Exclude them if they do not matter, or schedule the job for a time when they are not in use.

Backups are not being deleted

Retention only touches files named exactly like JobName_MM-dd-yyyy_HH-mm-ss.zip in the job's sub folder, and only after a successful backup. Backups made by hand and copied there with a different name are never touched.

The icon is missing

Check the hidden icons arrow next to the clock. If TrayBAK was started a second time, it simply brings the first copy forward.

TrayBAK does not start, or Windows asks for .NET

Install the Microsoft .NET 10 Desktop Runtime (64 bit) on the PC. TrayBAK does not bundle it.

TrayBAK says it cannot write to its config folder

TrayBAK keeps its settings and logs in folders next to TrayBAK.exe. Move the whole TrayBAK folder to a place you can write to, such as a folder in Documents or on another drive, not Program Files.

An error popup appeared

TrayBAK caught an unexpected problem and carried on. A short line is in the log and the technical details are in logs\errors.log. Keep that file if you need to report the problem.
